# Context 管理

本文件記錄 Context 管理的原則：agent 的 context 如何被消耗，以及設計文件、skill 與流程時如何控制這項成本。context 指 agent 單次工作時讀入的全部內容。名詞的定義見[詞彙表](../../CONTEXT.md)。

Context 管理是 Generator、所有 ADE 與 Forge 的根原則。設計任何會進入 context 的內容之前，先回答一個問題：這段內容值得在什麼時機、以什麼成本進入 context。本文件的其餘各節都是這個問題的展開，[知識的形式原則](./knowledge/README.md)則是它在知識庫的應用。

## Context 是稀缺資源

context 的容量有限，每一段讀入的內容都有兩種成本：

- **佔用容量。** 讀入的內容越多，留給工作本身的空間越少。
- **分散注意力。** 與當下工作無關的內容會和相關的內容競爭 agent 的注意力，提高判斷錯誤的機率。

因此，內容進入 context 的理由應是當下的工作需要它，而不是它可能有用。

## 載入時機

內容進入 context 的時機決定它的成本。下表以 Forge 的三種載體為例：

| 載體 | 進入 context 的時機 | 成本由誰付出 |
|---|---|---|
| 常駐區段 | 每個 session 開始時 | 每個 session，不論是否用到 |
| skill | `description` 在每個 session 開始時，本文在觸發時 | `description` 與常駐區段相同；本文只由觸發的 session 付出 |
| 知識庫 | agent 依導覽或搜尋讀取時 | 實際讀取的 session，成本是讀取的份量加上找到目標所需的跳轉 |

越早載入，成本越固定，與當下的工作是否相關無關；越晚載入，成本越貼近實際的需要，但 agent 必須知道何時、去哪裡取得。內容應放在仍能滿足需要的最晚時機。

## 常駐內容最小化

常駐的內容應只寫何時做什麼、去哪裡看，細節放在較晚載入的位置。常駐內容的作用是讓 agent 在需要時找得到細節，而不是提供細節本身。skill 的 `description` 同理，只寫觸發條件。

## 按需載入

只在部分情況需要的細節應拆到獨立的位置，用到時才讀取。判斷依據是讀取的時機，而不是篇幅。拆出的代價是需要時多一次跳轉，因此只有多數情況不需要的內容才值得拆出；每次都需要的內容即使篇幅長，也不應拆出。

## 導覽短、細節深

導覽應只提供讀者選擇下一步所需的資訊，細節留在導覽指向的位置。讀者從導覽出發，只讀與自己處境相關的分支，其餘分支不進入 context。
