# 知識與 skill

本文件規範 ADE 提供內容的兩種形式：知識與 skill 各自的職責，以及一項內容應寫在哪一種形式。名詞的定義見[詞彙表](../../CONTEXT.md)，考慮過的其他做法見[知識與 skill 分工的決策紀錄](../adr/0007-knowledge-records-facts-skill-wraps-execution.md)。

ADE 的目的是讓團隊內的人與 agent 對同一件事有一致的認知。流程、服務規格、概念、事件，只要能以文字描述，都是知識。Generator 定義知識與 skill 的框架，ADE 在這個框架下建立自己的知識體系，再注入 Forge，讓人與 agent 使用並持續迭代。

## 職責

知識與 skill 的職責不同，下表列出兩者的分工：

| 形式 | 職責 | 內容 |
|---|---|---|
| 知識 | 記錄事實本身 | 規則、判準、流程的定義、範本，以及每一步的產出 |
| skill | 封裝知識，讓 agent 執行 | 觸發條件、讀取知識的時機與順序、與工具互動的方式，以及呼叫的腳本 |

skill 需要知識的內容時，必須以引用指向知識，不得重述。重述的內容在知識修改後就會過期，agent 依 skill 執行、人依知識理解，兩者的認知隨之分歧。

## 界線

一項內容應寫在知識還是 skill，問的是：人不透過 agent 做這件事時，是否需要知道這項內容。需要的放在知識；只有 agent 執行時才需要的放在 skill。下表列出幾個例子：

| 內容 | 歸屬 | 理由 |
|---|---|---|
| commit 訊息的格式 | 知識 | 人自己 commit 時也必須遵守 |
| 撰寫 PRD 時必須回答的問題 | 知識 | PO 手寫 PRD 時也要回答 |
| 用提問工具一次問 2–3 題 | skill | 只和 agent 與使用者互動的方式有關 |
| 讀檔量大的階段交給 subagent 執行 | skill | 只和 agent 控制 context 的方式有關 |

這個判準來自 ADE 的目的。人以知識理解一件事，agent 同時讀知識與 skill；人也需要知道的內容只寫在 skill 時，人與 agent 的認知就不一致。反過來，只和 agent 操作有關的細節寫進知識，會提高人讀知識的查找成本。

## 腳本

腳本屬於 skill：skill 依知識撰寫腳本，把重複的操作封裝起來。知識庫不得放可執行的腳本。

知識的內文可以用程式碼區塊附上說明用的指令或範例，例如一則 commit 訊息的範例。判斷一段程式碼該放在哪裡，問的是它的目的：為了讓讀者理解的，屬於知識；為了被執行的，屬於 skill。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| skill 不重述知識、內容依界線歸屬 | skill：建立 skill 與建立知識的 skill 依本文件判斷內容的歸屬；seed：初始的 skill 與知識作為範例 |
| 知識庫不放可執行的腳本 | skill：建立知識的 skill 不把腳本放進知識庫；seed：初始知識作為範例 |
