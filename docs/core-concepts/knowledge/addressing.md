# 符號位址

本文件規範知識庫內的引用如何記錄：引用一律以符號位址指向知識單位，不使用路徑連結。知識單位與分類的定義見[知識的形式原則](./README.md)，考慮過的其他做法見[符號位址的決策紀錄](../../adr/0003-reference-knowledge-by-symbol-address.md)。

知識單位會延伸：檔案長成資料夾、資料夾多分一層。路徑連結在每一次延伸時失效；符號位址只記錄分類與名稱，單位在分類內的位置改變時，引用不需要修改。

## 形式

符號位址的形式為 `kb:<分類>/<名稱>`，例如 `kb:specs/checkout`。分類是知識庫根目錄下的第一層資料夾。分類與名稱之間不寫中間層。

符號在分類內遞迴解析，不限層數：解析到分類內任何深度、名稱相符的知識單位。

## 名稱

名稱不含副檔名，依知識單位的形態取值：

| 知識單位的形態 | 名稱 |
|---|---|
| 檔案 | 檔名去掉 `.md` |
| 帶有入口檔的資料夾 | 資料夾名 |

單位由檔案長成資料夾時，名稱不變，引用它的符號也不變。

名稱在整個分類內必須唯一，不論位於哪一層。兩個單位同名時，符號無法決定指向哪一個。

## 書寫方式

符號位址必須放在 code span 內，例如「見 `kb:specs/checkout`」。不在 code span 內的 `kb:` 字串不視為符號。

符號只指向知識單位，不指向單位內的章節。

## 符號與路徑的分工

符號與路徑 `knowledge/…` 服務不同的目的，依下表選用：

| 目的 | 寫法 | 例子 |
|---|---|---|
| 引用一個知識單位 | 符號位址 | 「規格見 `kb:specs/checkout`」 |
| 描述知識庫的結構，或指定建檔位置 | 路徑 | 「新的規格建在 `knowledge/specs/`」 |

前綴 `kb:` 與路徑 `knowledge/…` 在外觀上明顯不同，避免兩種寫法混用。

## 改名

知識單位改名時，同一次變更必須改完所有引用它的符號，不設別名。名稱在分類內唯一，因此以 grep 搜尋舊符號即可找出所有引用，並機械替換。

封存的文件，例如不再修改的歷史紀錄，同樣必須替換其中的符號。符號是位址，不屬於封存保護的內容；替換符號不改變文件的意思。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| 符號能解析，且在分類內只對應一個單位 | runner 的檢查：辨識 code span 中所有以 `kb:` 開頭的字串，解析失敗或對應到多個單位時報錯 |
| 引用使用符號、改名時替換所有引用 | skill：建立或修改知識的 skill 以符號引用其他單位，改名時一併替換；runner 的檢查在改名後發現遺漏 |
| 符號與路徑的分工 | skill；seed：初始內容以符號引用知識單位，作為範例 |
