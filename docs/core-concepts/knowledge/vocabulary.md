# 詞彙表

本文件規範 ADE 知識庫的詞彙表：專有名詞的定義集中在一份檔案，讓團隊成員與 agent 對名詞的理解一致。詞彙表如何支援搜尋見[搜尋](./search.md)，考慮過的其他位置與檔名見[詞彙表位置的決策紀錄](../../adr/0005-unify-ade-vocabulary-in-knowledge-root-context.md)。

## 定位

詞彙表定義一個領域內的專有名詞。每個需要討論的領域各有一份：生成器的詞彙表定義設計框架所用的名詞，ADE repo 的詞彙表定義團隊或公司在自己專業領域所用的名詞。兩者各管各的領域，互不衝突。

一個 ADE 只有一份詞彙表，涵蓋團隊的領域名詞，以及開發流程等 ADE 共用的名詞。

## 位置與檔名

詞彙表位於知識庫根目錄，檔名為 `CONTEXT.md`。放在知識庫內，詞彙表才會隨知識庫注入 ADE，讓 ADE 中的 agent 讀得到。

知識庫根目錄的檔案不屬於任何分類，因此詞彙表不以符號位址引用，也不需要 id。知識庫根目錄的 `README.md` 必須說明詞彙表的存在與用途。

## 詞條格式

詞彙表一個名詞一條，格式如下：

```md
**名詞（English）**：
一句話定義名詞所指的對象。
_Avoid_：實際發生過混淆的同義詞
```

英文名供檔名使用，規則見[檔名](./naming.md)；`_Avoid_` 列出的同義詞供搜尋時對照，見[搜尋](./search.md)。

## 用詞

知識內的用詞必須使用詞彙表中的正式名詞，不得改用 `_Avoid_` 列出的同義詞。需要詞彙表沒有的專有名詞時，必須先加入詞彙表，再於知識中使用。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| 知識庫根目錄有 `CONTEXT.md`，且根目錄 `README.md` 說明它 | seed |
| 詞條格式 | seed：初始的詞彙表作為範例；skill：新增詞條的 skill 依此格式撰寫 |
| 使用正式名詞、新名詞先加入詞彙表 | skill：建立或修改知識的 skill 先讀詞彙表，依正式名詞撰寫，需要新名詞時先加入 |
