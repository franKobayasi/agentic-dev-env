# 關聯

本文件規範知識之間的關聯記錄在哪一側，以及如何反向查找。關聯是樹以外的橫向引用，定義見[知識的形式原則](./README.md)；引用的寫法見[符號位址](./addressing.md)，考慮過的其他做法見[關聯方向的決策紀錄](../../adr/0008-record-relation-on-dependent-side.md)。

## 只記一側

同一個關聯必須只記錄在一側。兩側都記錄時，每次新增或刪除關聯都要修改兩處，漏改任何一處，兩側就不一致而無人察覺。

記錄的一側依下表決定：

| 關係 | 記錄的一側 | 例子 |
|---|---|---|
| 有依賴關係 | 依賴方，即需要對方才能被理解或執行的一側，指向被依賴方 | spec 依賴構成功能的服務，由 spec 列出涉及的服務；呼叫方依賴被呼叫方，由呼叫方記錄呼叫 |
| 沒有明確依賴的對等關係 | 後建立的一側 | 兩份 spec 互相參照，由後撰寫的一份記錄 |

由依賴方記錄，新增或刪除一份知識時只需要修改它自己。被依賴方通常比依賴方穩定，例如服務很少變動，spec 經常新增，因此不因依賴方的增減而修改。

## 反向查找

從被依賴方出發時，以搜尋找出依賴它的知識：被依賴方有 id 時搜尋它的 id，以名稱指稱時搜尋它的名稱。例如找出涉及某個服務的所有 spec 時，在 spec 所在的分類搜尋該服務的名稱。搜尋的方式見[搜尋](./search.md)。

刪除被依賴方之前，必須以反向查找找出所有依賴方並一併修改。以符號引用的關聯，遺漏時 runner 的檢查會報錯；以名稱指稱的關聯不經過引用檢查，只能靠搜尋找出。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| 只在依賴方記錄關聯 | skill：建立知識的 skill 只在依賴方記錄關聯；seed：初始知識只記錄一側，作為範例 |
| 刪除被依賴方前反向查找 | skill：刪除知識的 skill 先搜尋依賴方；runner 的檢查：以符號引用的關聯解析失敗時報錯 |

是否兩側都記錄同一個關聯無法機械判斷，因此 runner 不檢查。
