# 入口檔與索引檔

本文件規範知識庫中兩種導覽用的檔案：入口檔 `README.md` 與索引檔 `INDEX.md`。兩者服務讀者的不同處境，因此分成兩份檔案。知識單位與分層的原則見[知識單位與樹](./unit-and-tree.md)。

## 兩種檔案的分工

下表列出兩種檔案各自服務的處境與內容：

| | `README.md` | `INDEX.md` |
|---|---|---|
| 讀者的處境 | 第一次進入，或需要理解這部分的知識 | 已經知道要找什麼，只想找到那一筆 |
| 回答的問題 | 這是什麼知識、如何理解與使用、如何往下走 | 要找的那一筆在哪裡 |
| 是否必須 | 必須 | 選用，通常只用於集合型的資料夾 |
| 產生方式 | 手寫 | 由程式產生 |

兩個檔名一律使用大寫。不分大小寫的檔案系統會把 `index.md` 與 `INDEX.md` 視為同一個檔案，因此只能有一種寫法。

## 入口檔

知識庫的根目錄，以及每個屬於知識單位的資料夾，都必須有 `README.md`。入口檔依序包含下列內容：

1. 標題。這一層收錄什麼寫在 frontmatter 的 `description`，內文不重述，見[frontmatter 的欄位](./frontmatter.md)。
2. 本層特有的規則，上層已經定義的規則不重複；沒有就省略。
3. 導覽。

導覽的寫法依資料夾的性質決定：

| 資料夾的性質 | 導覽的寫法 |
|---|---|
| 主題型：各項內容不同 | 逐項列出，每一項寫明在什麼處境下閱讀，不寫內容摘要 |
| 集合型：一筆一檔、結構相同 | 寫檔名規則與新增方式，不逐筆列出；需要依屬性查找時，另設 `INDEX.md` |

導覽寫「何時閱讀」而不是摘要，因為讀者依自己的處境選擇下一步，例如「調整切分方式時」，而不是依內容選擇。

入口檔的篇幅不設上限。導覽無法讓讀者一次看完並選出下一步時，依知識單位與樹的原則多分一層。

知識庫根目錄的 `README.md` 是每一次查找的起點，另外必須說明查找方式：如何沿入口檔逐層往下找，以及如何以名稱直接搜尋。

## 索引檔

`INDEX.md` 只做索引：每一筆資料一列，列出查找時需要的屬性，不做說明。

`INDEX.md` 必須由程式從各筆資料的固定欄位產生，不得手寫，例如從 frontmatter 或 YAML 的欄位取值。同一份資訊同時寫在個別檔案與手寫的索引中，任何一邊修改時都必須同步另一邊；由程式產生，一致性由程式保證。考慮過的其他做法見[入口檔與索引檔分工的決策紀錄](../../adr/0002-separate-readme-and-generated-index.md)。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| 每個資料夾都有 `README.md` | runner 的檢查 |
| `INDEX.md` 與各筆資料一致 | runner 的檢查：重新產生後與現有內容比較，不一致即報錯 |
| 入口檔的內容順序與導覽寫法 | skill：建立或修改知識的 skill 依本文件撰寫入口檔；seed：初始的入口檔作為範例 |
| 根目錄 `README.md` 說明查找方式 | seed |
