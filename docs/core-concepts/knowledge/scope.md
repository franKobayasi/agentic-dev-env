# 收錄範圍

本文件規範知識庫收錄內容的原則、文件類型由誰定義，以及知識體系記錄在哪裡。知識與 skill 的分工見[知識與 skill](../knowledge-and-skill.md)，檔案格式與附件的規則見[知識單位與樹](./unit-and-tree.md)。

## 收錄範圍

框架不規定收錄範圍：能以文字描述的內容都可以收錄，例如流程、服務規格、概念與事件。收錄哪些內容、分成哪些分類，屬於 ADE repo 的知識體系設計。可執行的腳本不屬於知識，規則見[知識與 skill](../knowledge-and-skill.md)。

## 單一事實來源

同一份知識應只有一個權威來源。已有權威來源的知識，例如服務 repo 自己記錄的建置與測試步驟，不應複製進知識庫，知識庫只記錄取得的方式或引用它。知識庫與權威來源不一致時，以權威來源為準。

複本會在來源修改後過期而無人察覺，人與 agent 讀到不同的版本，ADE 讓認知一致的目的就會失敗。例外是 agent 進入權威來源之前就需要、而且很少變動的資訊，例如判斷要進入哪個服務 repo 時所需的技術棧概要；少量重複的成本低於每次都進入來源查找的成本。

## 文件類型

文件類型與它的生命週期由 ADE repo 定義，例如需求文件從草稿到實作完成的狀態流程。框架不定義任何文件類型，因為換一套分類後，這些類型就不存在。

文件類型的定義應寫在該類型所在資料夾的 `README.md`，包括用途、生命週期，以及各個狀態的意義；範本以 `_` 開頭，放在同一個資料夾。agent 建立這類文件時必定經過這個資料夾，在這裡讀到定義的成本最低。

## 知識體系的記錄位置

知識體系的現況寫在知識庫內，隨知識庫注入 ADE；設計的理由寫在 ADE repo 的決策紀錄，不注入。下表列出各項內容的位置與讀者：

| 內容 | 位置 | 讀者 |
|---|---|---|
| 有哪些分類、何時閱讀哪一個 | 知識庫根目錄 `README.md` 的導覽 | 查找知識的人與 agent |
| 分類的定位、文件類型與範本 | 各分類的 `README.md` | 建立知識的人與 agent |
| 分類方式的理由與考慮過的方案 | ADE repo 的決策紀錄 | 改變知識體系結構的 ADE repo 維護者 |

現況必須注入，因為 ADE 中的 agent 要讀得到，才能判斷新知識屬於哪個分類；理由只在改變結構時需要，依 [Context 管理](../context-management.md)不注入。各分類的定位只寫在該分類的 `README.md`，不另寫一份體系設計文件，避免同一份內容有兩份。考慮過的其他做法見[知識體系記錄位置的決策紀錄](../../adr/0010-knowledge-system-state-in-injected-readmes.md)。

## 落實方式

本文件的原則依下表落實：

| 原則 | 落實的機制 |
|---|---|
| 單一事實來源 | skill：建立知識的 skill 在收錄前確認內容沒有其他權威來源；seed：初始知識作為範例 |
| 文件類型的定義位置 | skill：建立新文件類型的 skill 依本文件撰寫；seed：初始的文件類型在所屬資料夾的 `README.md` 定義 |
| 知識體系的記錄位置 | seed：初始的根目錄與分類 `README.md` 記錄現況，並提供撰寫決策紀錄的 skill |
