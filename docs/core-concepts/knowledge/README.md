# 知識的形式原則

本文件定義知識庫在形式上遵守的原則：知識如何切分、組織、索引與引用，讓人與 agent 以最低的成本找到目標知識，並讓知識庫的維護成本維持在低點。名詞的定義見[詞彙表](../../../CONTEXT.md)。

本原則只規範形式，不規範內容。知識庫分成哪些分類、各分類的定位與內容，由各 ADE repo 自行設計。判斷一條規則是否屬於本原則，問的是：換一套完全不同的分類，這條規則是否仍然成立。成立者屬於本原則；不成立者屬於 ADE repo 的知識體系設計。

本文件的讀者是生成器的維護者。ADE repo 不閱讀本文件，而是透過 seed 的初始結構、runner 的檢查與 skill 的步驟，接收這些原則落實後的結果。修改 seed 的知識庫結構、runner 的檢查規則，或建立知識的 skill 之前，應先對照本文件。

## 衡量標準

所有形式原則都以兩個衡量標準做取捨。下表列出兩者的構成：

| 標準 | 構成 |
|---|---|
| 查找成本 | 找到目標知識所需的跳轉次數乘以每次讀取的份量，加上找錯或找不到的機率 |
| 管理成本 | 一次變更需要修改的位置數，加上內容過期而無人察覺的機率 |

兩者經常互相牽制。例如目錄切得越細，每次讀取的份量越少，但跳轉次數與需要維護的入口檔越多。

## 構件

知識庫由五個構件組成，每個構件主要影響其中一個衡量標準。下表列出各構件的定義：

| 構件 | 定義 | 主要影響 |
|---|---|---|
| 知識單位 | 一份知識，依份量是一個檔案，或一個帶有入口檔的資料夾 | 兩者 |
| 樹 | 每個知識單位只有一個上層，構成唯一的主要路徑 | 查找成本 |
| 索引 | 每個資料夾的入口檔，引導讀者選擇下一層 | 查找成本 |
| 關聯 | 樹以外的橫向引用 | 管理成本 |
| 搜尋 | 以名稱直接定位知識，例如 grep 或 glob | 兩者 |

各構件分別服務讀者的不同處境，如下表所示：

| 讀者的處境 | 負責的構件 |
|---|---|
| 不知道知識庫裡有什麼 | 樹與索引：從根目錄的入口檔逐層往下找 |
| 知道要找的名稱或用詞 | 搜尋：直接定位，不經過樹 |
| 找到一份知識後，需要與它相關的知識 | 關聯：沿引用找到另一份 |

搜尋讓樹不必完美，但前提是用詞一致。

## 落實方式

原則不以文件的形式發給 ADE repo，而是落實成三種機制。下表列出各機制負責的範圍：

| 機制 | 落實的範圍 | 作用時機 |
|---|---|---|
| seed | 符合原則的初始結構與範例，例如每個資料夾的入口檔 | create 建立 ADE repo 時，只作用一次 |
| runner 的檢查 | 可以機械判斷的規則，例如入口檔是否存在、引用能否解析 | ADE repo 執行檢查時 |
| skill | 無法機械判斷的規則，例如入口檔的導覽是否寫明何時閱讀 | agent 建立或修改知識時 |

每份原則文件必須寫明其中每條原則的落實方式。沒有任何機制落實的原則，不會影響 ADE repo 的實際樣貌。
