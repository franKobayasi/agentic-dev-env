# Spec 與實作對齊

開發完成後的文件收尾：讓 spec 回到「描述現況」的狀態。

## 流程

1. 確認這次開發對應的 PRD 與受影響 spec（從使用者、branch 或 PR 上下文取得；不確定就問）
2. 逐項核對：對照 `workspaces/` 下的實際實作，檢查 spec 中該 PRD 的每個 `🚧 尚未實作` 區塊
   - 已實作且行為一致 → 準備移除標記
   - 實作與 spec 不符 → 以**實作為準**修改 spec 內容，並記下差異
   - 沒做的項目 → 保留標記，記下
3. 依 `ade-contribute` skill 的流程 clone ADE repo 並修改：
   - 移除已實作區塊的 🚧 標記、套用與實作對齊的修改
   - 全部驗收項完成時，把 PRD 狀態改為「已實作」
4. 開 PR，描述中列出：移除了哪些標記、spec 與原規劃的差異（給 PO 判斷是否接受）、未完成保留的項目
