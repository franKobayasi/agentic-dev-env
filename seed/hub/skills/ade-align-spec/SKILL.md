# 產品規格與實作對齊

開發完成後的收尾：讓產品規格回到描述現況的狀態。尚未實作標記的格式見[產品規格的入口檔](kb:specs/f2e5d1)，PRD 的生命週期見[PRD 的入口檔](kb:prd/c66c02)。

1. 確認這次開發對應的 PRD 與受影響的產品規格，從使用者、分支或 PR 的脈絡取得；不確定時詢問使用者。記下 PRD 的 id。
2. 依 `ade-contribute` 的流程取得工作副本，核對與修改都以工作副本為唯一基準。ADE 中 `.claude/ade/` 的副本可能過期，例如 PO 合併了寫入產品規格的 PR 後還沒有人執行 update，副本中根本沒有那些標記，因此只能用於導覽。
3. 找出本次 PRD 的標記：在工作副本的產品規格中執行 `grep -n "尚未實作" <檔案>` 列出全部標記行，再只處理含 `kb:prd/<本次 PRD 的 id>` 的行。其他 PRD 的標記與它們描述的內容一律不動。
4. 對照 `workspaces/` 中的實作，逐一核對屬於本次 PRD 的區塊：
   - 已實作且行為一致：刪除該標記行，保留內容。
   - 實作與產品規格不符：以實作為準修改產品規格，並記下差異。
   - 尚未實作：保留標記，並記下。
5. 在工作副本套用修改；驗收條件全部完成時，把 PRD 的 `status` 改為「已實作」。
6. 在工作副本根目錄執行 `node cli.js check`，再依 `ade-contribute` 的流程開 PR。PR 的描述列出移除了哪些標記、產品規格與原規劃的差異，供 PO 判斷是否接受，以及保留未完成的項目。
