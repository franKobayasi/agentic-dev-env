# 服務

本分類只收 agent 進入服務 repo 之前必需的最小資訊，以及跨服務的呼叫關係。服務內部的規範、架構與建置、啟動、測試步驟歸服務 repo 自己的文件，不收進本分類。技術棧概要是刻意保留的少量重複：agent 進入服務 repo 之前就需要它來判斷，而且很少變動。

## 規則

描述檔遵守下列規則：

- 每個服務一份描述檔 `<服務名稱>.yaml`，欄位依 `_template.yaml`。描述檔是本資料夾的附件，不帶 id；其他知識以服務名稱指稱個別服務。
- `repo` 的 `url` 與 `branch` 必填，agent 依它 clone 服務 repo。
- 呼叫關係只記在呼叫方的 `calls`，被呼叫方不記錄反向的關係。要找出呼叫某個服務的其他服務，在本資料夾搜尋該服務的名稱。
- 服務與產品規格的關聯由產品規格記錄，描述檔不記錄。
- 服務退役時刪除描述檔，git 的歷史即是封存。本分類只描述目前存在的服務，不設狀態欄位，避免 agent clone 已退役的 repo。

## 導覽

本資料夾是集合型，依需要選用下列方式：

- 找特定服務：讀 `<服務名稱>.yaml`。不確定名稱時，讀各描述檔的 `name` 與 `description`，或使用 `ade-list-service`。
- 新增服務：使用 `ade-add-service`，或複製 `_template.yaml` 為 `<服務名稱>.yaml` 後填寫。
