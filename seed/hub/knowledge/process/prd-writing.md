# 撰寫 PRD

本文件說明撰寫 PRD 時要回答什麼、寫在哪裡，以及送出前要檢查什麼。PRD 的定位與生命週期見[PRD 的入口檔](kb:prd/c66c02)。

## 要回答的問題

撰寫 PRD 前，下列七個問題都必須有實質的答案，或明確說明不在範圍內：

1. 想做什麼？用一句話說明。
2. 為誰做？以敘述描寫使用者，不寫人口統計。
3. 解決什麼痛點？只寫痛點，不寫解法。
4. 為什麼是現在？例如期限、法規、客戶或競爭。
5. 怎麼算成功？必須可量測，包含基準值、目標值與量測方式。
6. 範圍：做什麼，以及明確不做什麼。
7. 影響哪些服務，相依哪些既有的 PRD 或產品規格？

答案含糊時繼續追問，不替提出者猜測；沒有答案的問題寫進「開放問題」。這個階段不談實作與資料結構。

## 各區塊的內容

下表列出範本各區塊的內容與來源：

| 區塊 | 內容 | 來源 |
|---|---|---|
| 背景與目標 | 痛點、時機與成功標準 | 問題 3、4、5 |
| 非目標 | 明確不做的部分，不得空白 | 問題 6 |
| 需求描述 | GWT 決策表，一列一個情境，具體到能開發；不寫故事散文，每列的例外處置不得空白 | 問題 1、2 |
| 影響服務 | 涉及的服務名稱與各自要改什麼 | 問題 7 |
| 驗收條件 | 每條都可測試；「好用」「快」這類形容詞換成可驗證的敘述 | 問題 5、需求描述 |
| 開放問題 | 尚未定案、待 PO 決定的點 | 沒有答案的問題 |
| 產品規格異動摘要 | 寫入產品規格後填寫：動了哪些產品規格、各自的異動重點 | `ade-prd-to-spec` |

## 盲點

送出前逐項確認下列盲點，每一項都要有明確的答案，或明確說明不在範圍內：

- **邊界與錯誤**：輸入不合法、資源不存在、操作中斷、併發衝突時，各是什麼行為？
- **跨服務影響**：有沒有漏列受影響的服務？服務間的呼叫順序與失敗處理為何？
- **權限與安全**：誰能使用這個功能？資料存取的邊界在哪裡？
- **相容性**：既有資料要遷移嗎？舊版本的客戶端或既有 API 的使用者會受影響嗎？
- **驗收條件**：每一條都可測試嗎？
- **非目標**：最容易被誤以為包含在內的相鄰功能是什麼？

答案依下列方式回填：邊界與錯誤寫成決策表的新列或該列的例外處置，範圍外的寫進「非目標」，尚未定案的寫進「開放問題」。
